# QNX mkifs buildfile lint rules

Grounding: QNX SDP 8.0 [mkifs reference](https://www.qnx.com/developers/docs/8.0/com.qnx.doc.neutrino.utilities/topic/m/mkifs.html), sections Buildfiles and Attributes. The table quotes or paraphrases the sentence that supports each check. This checker is a static syntax aid, not a full mkifs parser. It does not validate inline script contents, attribute value semantics, or whether host files exist. It has not been validated against the real mkifs binary; that requires QNX SDP, which is unavailable here.

| Rule ID | Severity | Check | QNX documentation and supporting sentence |
|---|---|---|---|
| BF-ATTR-UNTERMINATED | error | Attribute `[` has no closing `]`. | [Buildfiles](https://www.qnx.com/developers/docs/8.0/com.qnx.doc.neutrino.utilities/topic/m/mkifs.html#mkifs__Buildfiles): attributes are enclosed in square brackets. |
| BF-ATTR-MULTIPLE-GROUPS | error | Attributes use more than one bracket group before a file spec. | [Buildfiles](https://www.qnx.com/developers/docs/8.0/com.qnx.doc.neutrino.utilities/topic/m/mkifs.html#mkifs__Buildfiles): “when combining attributes ... enclose both attribute tokens in the same pair of square brackets.” |
| BF-ATTR-EQUALS-SPACING | error | Attribute `=` has surrounding whitespace. | [Buildfiles](https://www.qnx.com/developers/docs/8.0/com.qnx.doc.neutrino.utilities/topic/m/mkifs.html#mkifs__Buildfiles): “Don't put any spaces around the equals sign.” |
| BF-ATTR-UNKNOWN | warning | Attribute name is absent from the mkifs attribute list. | [Attributes](https://www.qnx.com/developers/docs/8.0/com.qnx.doc.neutrino.utilities/topic/m/mkifs.html#mkifs__Attributes): the command “supports the following attributes” (the documented list). |
| BF-ATTR-KIND | error | Boolean/value attribute is used in the opposite documented form. | [Buildfiles](https://www.qnx.com/developers/docs/8.0/com.qnx.doc.neutrino.utilities/topic/m/mkifs.html#mkifs__Buildfiles): boolean attributes are prefixed with `+` or `-`; value attributes end with `=` and a value. `compress` supports both listed forms. |
| BF-COMMENT-SPACE | warning | `#` is glued to a command. | [Buildfiles](https://www.qnx.com/developers/docs/8.0/com.qnx.doc.neutrino.utilities/topic/m/mkifs.html#mkifs__Buildfiles): “There must be a space between a buildfile command and the pound sign.” |
| BF-INLINE-OPEN-CONTENT | error | Content occurs after `{` on the opening line. | [Buildfiles](https://www.qnx.com/developers/docs/8.0/com.qnx.doc.neutrino.utilities/topic/m/mkifs.html#mkifs__Buildfiles): inline contents “can't be on the same line as the opening ... brace.” |
| BF-INLINE-CLOSE-CONTENT | error | Content precedes `}` on its closing line. | [Buildfiles](https://www.qnx.com/developers/docs/8.0/com.qnx.doc.neutrino.utilities/topic/m/mkifs.html#mkifs__Buildfiles): inline contents “can't be on the same line as the ... closing brace.” |
| BF-INLINE-UNCLOSED | error | Inline file has no standalone closing brace before EOF. | [Buildfiles](https://www.qnx.com/developers/docs/8.0/com.qnx.doc.neutrino.utilities/topic/m/mkifs.html#mkifs__Buildfiles): inline contents are enclosed in braces and closing braces must be escaped inside contents. |
| BF-INLINE-STRAY-CLOSE | error | `}` appears outside an inline file. | [Buildfiles](https://www.qnx.com/developers/docs/8.0/com.qnx.doc.neutrino.utilities/topic/m/mkifs.html#mkifs__Buildfiles): braces delimit an inline definition. |
| BF-FILE-QUOTE | error | Filename quote is unbalanced. | [Buildfiles](https://www.qnx.com/developers/docs/8.0/com.qnx.doc.neutrino.utilities/topic/m/mkifs.html#mkifs__Buildfiles): a filename may be enclosed in double quotes. |
| BF-PATH-BACKSLASH | note | Backslash appears as a path separator; recommend `/`. | [Buildfiles](https://www.qnx.com/developers/docs/8.0/com.qnx.doc.neutrino.utilities/topic/m/mkifs.html#mkifs__Buildfiles): forward slashes are “strongly recommended” because backslashes in filepaths may adversely affect the buildfile. |
